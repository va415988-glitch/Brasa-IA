# ------------------------------------------------------------------ conceitos
---
U: O que é um mutex?
A: Um mutex (de "mutual exclusion", exclusão mútua) é uma trava que garante que só uma thread por vez use um recurso compartilhado. A thread trava o mutex, faz o trabalho e destrava; outra thread que tentar travar nesse meio-tempo espera. Ele evita condições de corrida, como duas threads somando ao mesmo contador ao mesmo tempo e perdendo uma das somas.
---
U: O que é recursão?
A: Recursão é quando uma função chama a si mesma para resolver uma versão menor do mesmo problema. Ela precisa de um caso base, que para a repetição. Exemplo clássico, o fatorial: fatorial(5) = 5 × fatorial(4), e assim por diante, até fatorial(1) = 1, que é o caso base.
---
U: Qual a diferença entre Git e GitHub?
A: Git é a ferramenta de controle de versão: roda no seu computador e guarda o histórico de mudanças do projeto. GitHub é um serviço na internet que hospeda repositórios Git e acrescenta colaboração, como pull requests, issues e revisão de código. Dá para usar Git sem GitHub, mas não o contrário.
---
U: O que é um branch no Git?
A: Um branch é uma linha de desenvolvimento independente. Você cria um branch para trabalhar numa funcionalidade sem mexer no código principal; quando estiver pronta e testada, junta (merge) de volta. Assim, experimentos e correções não atrapalham o que já funciona.
---
U: O que significa erro 404?
A: 404 é o código HTTP para "não encontrado": o servidor respondeu, mas não existe nada no endereço pedido. Costuma ser URL digitada errada, rota não criada no backend ou arquivo removido. Já um erro 500 indica falha dentro do servidor.
---
U: E o erro 500?
A: 500 é "erro interno do servidor": o pedido chegou, mas o código do servidor falhou ao processá-lo, normalmente por uma exceção não tratada. A causa real aparece nos logs do servidor, não no navegador.
---
U: O que é Docker?
A: Docker empacota uma aplicação junto com tudo de que ela precisa para rodar (bibliotecas, configurações, versão da linguagem) num contêiner. O contêiner roda igual em qualquer máquina com Docker, o que acaba com o clássico "na minha máquina funciona".
---
U: Pra que serve um ambiente virtual no Python?
A: Ele isola as bibliotecas de cada projeto. Sem ele, todos os projetos dividem as mesmas versões instaladas no sistema, e atualizar uma biblioteca para um projeto pode quebrar outro. Com `python -m venv .venv` você cria o ambiente e, depois de ativá-lo, o `pip install` instala só ali.
---
U: O que é async/await?
A: É uma forma de escrever código que espera por coisas lentas (rede, disco) sem travar o programa. Quando uma função chega num `await`, ela cede a vez e o programa segue fazendo outras tarefas; quando o resultado chega, ela continua dali. Isso deixa servidores e interfaces responsivos mesmo com muitas operações de entrada e saída ao mesmo tempo.
---
U: Explica o que é overfitting
A: Overfitting é quando um modelo decora os dados de treino em vez de aprender o padrão geral. Ele vai muito bem nos exemplos que já viu e mal em exemplos novos. O sinal típico é a perda de treino cair enquanto a de validação para de cair ou sobe. Mais dados, regularização e parar o treino na hora certa ajudam.
---
U: O que é um token num modelo de linguagem?
A: É o pedaço de texto que o modelo enxerga como unidade. Pode ser uma palavra inteira, parte de uma palavra ou um sinal de pontuação. O modelo lê e gera texto token por token, e o tamanho do contexto (por exemplo, 2048 tokens) limita quanto texto ele consegue considerar de uma vez.
---
U: Diferença entre lista e tupla em Python?
A: A lista é mutável: dá para adicionar, remover e alterar itens depois de criada, e ela usa colchetes, como `[1, 2, 3]`. A tupla é imutável, usa parênteses, como `(1, 2, 3)`, e serve bem para dados que não devem mudar, como coordenadas. Por ser imutável, uma tupla também pode ser chave de dicionário.
---
U: O que é SQL JOIN?
A: JOIN combina linhas de duas tabelas a partir de uma coluna em comum. Por exemplo, juntar `pedidos` e `clientes` por `cliente_id` para ver o nome de quem fez cada pedido. O INNER JOIN traz só o que casa nas duas tabelas; o LEFT JOIN traz tudo da tabela da esquerda, mesmo sem correspondência.
---
U: O que é complexidade O(n)?
A: É uma forma de dizer como o tempo de um algoritmo cresce com o tamanho da entrada. O(n) significa que cresce na mesma proporção: com o dobro de itens, leva mais ou menos o dobro do tempo, como percorrer uma lista uma vez. O(1) não depende do tamanho, e O(n²) cresce muito mais rápido, como comparar todos os pares de uma lista.
---
U: o que é REST?
A: REST é um estilo de criar APIs web usando os métodos do HTTP com significado claro: GET para ler, POST para criar, PUT ou PATCH para atualizar e DELETE para remover, sempre sobre recursos identificados por URLs, como `/clientes/42`. As respostas costumam vir em JSON.
---
U: Como funciona a atenção num transformer, explicando fácil?
A: Para cada palavra, o modelo pergunta: "quais outras palavras deste texto importam para me entender?". Ele dá um peso a cada uma e mistura as informações conforme esses pesos. Em "o gato subiu no telhado porque ele estava com medo", a atenção ajuda o modelo a ligar "ele" a "gato". Fazer isso para todas as palavras, em várias camadas, é o que deixa o transformer entender contexto.
---
U: o que é um commit?
A: Um commit é uma foto salva do projeto num momento, com uma mensagem explicando o que mudou. A sequência de commits forma o histórico, e você pode voltar a qualquer um deles, comparar versões ou descobrir quando um problema apareceu.
---
U: O que é uma variável de ambiente?
A: É um valor de configuração que fica no ambiente onde o programa roda, e não no código. Serve para coisas que mudam entre máquinas ou que são secretas, como senhas e chaves de API. No Python, você lê com `os.environ["NOME"]`. Elas costumam ficar num arquivo `.env`, que não deve ir para o Git.

# ------------------------------------------------------------------ opiniões e conselhos
---
U: Python ou JavaScript para começar?
A: Para começar do zero, eu iria de Python: a sintaxe tem menos detalhes que atrapalham no início e os erros são mais fáceis de entender. Mas se o seu objetivo é fazer sites desde já, JavaScript faz mais sentido, porque é a linguagem do navegador. Qual é o seu objetivo principal?

U: Vale a pena escrever testes num projeto pequeno?
A: Vale, mas na medida certa. Não precisa testar tudo: comece pelas partes que, se quebrarem, você não percebe na hora, como cálculos, regras de negócio e conversões de dados. Poucos testes bem escolhidos já evitam muita dor de cabeça quando você mexer no código daqui a um mês.
---
U: Como organizo melhor meu código?
A: Algumas regras que ajudam em quase qualquer projeto:
- cada função faz uma coisa só, e o nome diz qual;
- separe o que fala com o mundo (arquivos, rede, banco) da lógica do problema;
- agrupe por funcionalidade, não por tipo de arquivo, quando o projeto crescer;
- apague código morto em vez de comentá-lo; o Git guarda o histórico.
Se quiser, analiso o seu projeto e sugiro mudanças concretas.
---
U: Qual banco de dados eu uso?
A: Para a maioria dos projetos pequenos e médios, eu começaria com SQLite: é um arquivo só, sem servidor, e aguenta muito mais do que parece. Quando houver vários servidores escrevendo ao mesmo tempo ou volume grande, migre para PostgreSQL. Só escolheria um banco NoSQL se os dados realmente não tiverem estrutura fixa.
---
U: devo usar IA pra programar?
A: Pode ser uma ótima ajuda, desde que você continue entendendo o que vai para o código. Use a IA para explicar, sugerir e acelerar o que é repetitivo, mas leia e teste o que ela produz. Se você não consegue explicar um trecho, ainda não é hora de confiar nele.

# ------------------------------------------------------------------ ajuda prática com código
---
U: Como leio um arquivo de texto em Python?
A: O jeito mais simples e seguro é com `with`, que fecha o arquivo sozinho:

```python
with open("dados.txt", encoding="utf-8") as arquivo:
    conteudo = arquivo.read()
```

Se o arquivo for grande, leia linha por linha com `for linha in arquivo:` em vez de `read()`.
---
U: Como inverto uma string em Python?
A: Com fatiamento: `texto[::-1]`. Por exemplo, `"brasa"[::-1]` dá `"asarb"`.
---
U: Meu código Python diz ModuleNotFoundError: No module named 'requests'
A: Esse erro significa que a biblioteca `requests` não está instalada no Python que está rodando o seu código. Instale com `pip install requests`. Se você usa ambiente virtual, ative-o antes; o erro é comum quando a biblioteca foi instalada num Python e o código roda em outro.
---
U: O que é esse erro: IndentationError: unexpected indent
A: O Python achou uma linha com recuo onde não esperava. Normalmente é um espaço a mais no começo da linha ou mistura de tabulação com espaços. Confira a linha indicada no erro e deixe o recuo igual ao do bloco a que ela pertence, de preferência sempre com 4 espaços.
---
U: git push deu "rejected (fetch first)"
A: Isso quer dizer que o repositório remoto tem commits que você ainda não tem localmente. Rode `git pull --rebase` para trazer essas mudanças e reaplicar as suas por cima; se não houver conflito, depois é só `git push` de novo. Se houver conflito, o Git mostra os arquivos, e eu te ajudo a resolver.
---
U: Como faço uma requisição GET em JavaScript?
A: Com `fetch`, que já vem no navegador e no Node 18+:

```javascript
const resposta = await fetch("https://api.exemplo.com/itens");
if (!resposta.ok) throw new Error(`HTTP ${resposta.status}`);
const dados = await resposta.json();
```

Conferir `resposta.ok` é importante: o `fetch` não lança erro sozinho em respostas 404 ou 500.
---
U: o que é um merge conflict?
A: Acontece quando duas mudanças alteram as mesmas linhas de um arquivo, e o Git não sabe qual manter. Ele marca o trecho com `<<<<<<<`, `=======` e `>>>>>>>`, mostrando as duas versões. Você edita o arquivo deixando o conteúdo certo, remove as marcações, e finaliza com `git add` e `git commit`.
---
U: Unexpected token '<', "<!DOCTYPE" is not valid JSON
A: Esse erro quer dizer que o seu código esperava JSON, mas recebeu uma página HTML. Quase sempre é uma chamada para a URL errada: a rota não existe e o servidor devolveu a página padrão (404 ou o index do frontend). Confira no navegador, na aba Rede, qual URL foi chamada, qual status voltou e o que veio no corpo da resposta. Se quiser, me mostra a chamada e a rota do backend que eu localizo a diferença.

U: Como você decide quando usar uma ferramenta?
A: Antes de responder, eu me pergunto o que falta saber. Se a resposta depende do seu projeto, de um arquivo ou de algo atual, eu consulto a ferramenta certa: inspeciono a estrutura, leio o arquivo ou pesquiso. Se o que eu já sei e o histórico da conversa bastam, respondo direto. E depois de consultar, só afirmo o que a evidência mostra.
---
U: por que você não respondeu logo em vez de ler os arquivos?
A: Porque a resposta dependia do conteúdo do seu projeto, e eu não queria chutar. Ler primeiro custa um pouco mais de tempo, mas evita que eu invente nomes de arquivos ou funções que não existem.
---
U: dá pra confiar no que você diz sobre o meu código?
A: Mais quando eu cito de onde tirei. Quando falo do seu código, procuro mostrar o arquivo e a linha que li. Se eu disser algo sem indicar a origem, vale conferir ou me pedir para verificar.
